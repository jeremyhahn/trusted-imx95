# Plan: #141, the Codex code-review workflow

## Objective

Add `.github/workflows/code-review.yml`, a copy of the handbook template
`software/templates/github-actions/code-review.yml` v5.12.3, so that pull
requests here get the Codex review and its required `Code Review (codex)`
check. It runs on `pull_request_target`, so it reads from main and must land
there first.

## Slices

1. Copy the template verbatim and change only its CUSTOMIZE fields:
   - scope job: `CI_FILE` `.github/workflows/ci.yml` and `GATE_JOB`
     `ci-gate` (`CI Gate`) are already the template's values. `PROTECTED`
     adds `releasability` and `signatures`, this repository's two
     `pull_request_target` workflows, which the template's
     `PROTECTED_WORDS` doesn't match;
   - `DOCS_PATHS`, `NO_REVIEW_PATHS` and `COORDINATOR_TURNS` stay at the
     template defaults;
   - the opencode job stays as it is: it runs only on Gitea (v5.9.0), so
     it never runs on GitHub, and changing `runs-on` would diverge from
     the template for no effect.
   Tests: the template's `testdata/code-review-*-tests.py` run against the
   copy (`CODE_REVIEW_TEST_YML`, which only the modzip suite reads), plus
   actionlint through `make lint`.

## Out of scope

- Wiring the handbook's regression tests into this repository's CI. The
  template README asks nothing of a copy, and the tests live in the
  handbook.
- Setting the repository variable `CODEX_REVIEWER` and admitting the
  repository to the `codex` runner, which the Tenant Agent and Infra do.
