# Plan: #161, the test-PKI signed boot image (no flash)

## Objective

Assemble the full i.MX 95 B0 (SPSDK `mimx9596` `b0`) boot image from its
inputs, sign every container with a throwaway test PKI generated outside the
tree, verify every container, and show that one flipped byte in any signed
payload is rejected. Nothing touches a board, a fuse, a life cycle, RPMB or a
block device. Signing tool: the pinned SPSDK 3.13.0 (owner decision,
docs/boot-container/signing-tool-options.md).

## Slices

1. Inputs. `scripts/boot-image-inputs.sh` collects System Manager, the
   Cortex-M7 image, BL31, tee.bin, U-Boot and the ELE firmware into one
   directory with an `inputs.txt` (name, source, SHA-256). `boot-container/inputs.lock`
   pins the U-Boot source (commit, archive SHA-256) and the ELE firmware
   installer (URL, SHA-256). `--check` validates the pins offline; a supplied
   file or a fetched pin that differs fails closed. Test: `test/boot_image_test.sh`
   (inputs part), in `make test`.
2. Assembly and signing. `scripts/ahab/boot-image.sh` and the config template
   `scripts/ahab/boot-image.yaml`; `make boot-image-test` signs three
   containers with a test PKI, verifies the image, writes the image and a
   SHA256SUMS to a git-ignored out dir, then flips one byte in each signed
   payload and requires verification to fail. An input that cannot be built in
   the lane is a labelled stand-in payload for that one container entry.
   The signing step refuses a payload whose SHA-256 differs from its
   `inputs.txt` entry (changed after collection), and the tamper checks
   cannot be skipped (no `--no-tamper`).
3. The Cortex-M7 image is external: trusted-firmware's (docs/SPEC.md). Input
   collection takes it with `BI_M7=<file>` and otherwise uses the labelled
   stand-in. An in-repo idle image tried in an earlier resume was removed as
   outside this row.
4. Docs. `docs/boot-container/boot-image.md` (provisional), linked from
   architecture.md.

5. Container walk. `test/boot_image_test.sh` finds the three container
   headers by walking `[0, smallest parsed image_offset)` in 0x400 steps and
   asserts the bound lies past the last header (0x8000). Offset base, observed
   in the test output under the pinned SPSDK 3.13.0 (not read from SPSDK
   source): the parsed `image_offset` values are `0xc000 0xd400 0xe800 0xfc00
   0x11000 0x12400`, container headers at 0x0, 0x4000, 0x8000. They are
   absolute (image start): every one is past the last header, spaced 0x1400
   apart (the 5120-byte padded payloads), and the last ends at 0x13800, the
   image size. Relative to their own header they would run past the end of the
   image. So no header offset is added. The test prints the values on each run.
6. A55 inputs. `--collect` accepts `bl31.bin` and `tee.bin` from `.secure-world/out` as
   real only if `SHA256SUMS` matches both files and the `lock:` line of `build-info.txt` is the
   SHA-256 of this tree's `secure-world/bsp.lock`; any miss fails closed, no `inputs.txt`. Tests: a
   changed byte, a missing SHA256SUMS or build-info.txt, a different `lock:`, a missing entry.
7. A55 addresses. Container 3's `tee` entry is explicit at `0x8C000000` (TF-A `platform.mk:56`,
   OP-TEE `conf.mk:729` and `:299`, cited in the yaml); `atf` at `0x8A200000` is TF-A
   `platform_def.h:34` (`BL31_BASE`), equal to SPSDK's default. `test/boot_image_test.sh` asserts three
   `cortex-a55` entries in the order atf, uboot, tee, and the atf and tee load and entry addresses.
   Mutation (2026-11-23, scratch clone under the git-ignored `out/`): tee `load_address` set to
   `0x8C001000`, `bash test/boot_image_test.sh` printed `FAIL a55: the tee load_address is
   0x8c000000 (parsed '0x8c001000')` and `1 failed`; reverted with `git checkout --
   scripts/ahab/boot-image.yaml`.
8. Whole-image policy and negatives. `boot-image.sh` runs `policy-check.sh` on the image against the new
   `scripts/ahab/boot-image-manifest.yaml` (policy file from the parse, in the work directory) and also
   flips one byte in each container header and signature block (6 more `tamper:` lines). Tests: two
   manifest mutations, and cases (a) truncated, (b) a gap byte, (c) a fresh test PKI against the first
   policy file, (d) `USED_SRK_ID` 1. Mutations checked 2026-11-24: an always-accepting header-tamper
   check stopped the run; case (b) with the policy check replaced failed its test.

## Out of scope

Real keys, the HSM, fuses, life cycle, a board, flashing, encryption, the
decision on which stand-ins become real inputs (a CI or build-host lane), the
boot ROM load order on silicon (IMX95RM is missing).
