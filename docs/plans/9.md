# Plan: issue #9, host-side AHAB container signing pipeline (SPSDK, test PKI)

Row `boot-container` of [docs/SPEC.md](../SPEC.md), Epic 1 (#12). Owner decision of 2026-11-21:
SPSDK 3.13.0, ECDSA P-384, board silicon i.MX 95 B0 (`/sys/devices/soc0/revision` reads 2.0), so
SPSDK family `mimx9596`, revision `b0`.

## Objective

`make ahab-sign-test` generates a throwaway ECDSA P-384 test PKI outside the tree, builds an AHAB
container for `mimx9596` B0 around a random test payload with a hash-pinned SPSDK 3.13.0, signs it,
verifies it with `nxpimage ahab verify`, prints the test SRK table hash, and leaves no key material
anywhere. A tampered copy fails the same verify step.

## Slices, in order

1. This plan.
2. `test/ahab_sign_test.sh`, failing on main. It asserts:
   (a) `make ahab-sign-test` succeeds and the container it hands back (`AHAB_OUT_DIR`) passes
   `scripts/ahab/sign-test.sh verify`; (b) a copy with one byte of the signature flipped, and one
   with one byte of the payload flipped, are rejected; (c) no file in the clone is new or changed
   after the run and none holds a private key; (d) the run fails, naming the pin, when the venv's
   SPSDK is not 3.13.0.
3. `scripts/ahab/requirements.txt` (the closure, every file by SHA-256) and
   `scripts/ahab/build-requirements.txt` (the build backend for the hexdump and libuuu sdists),
   installed by `scripts/ahab/spsdk-venv.sh` with `pip install --require-hashes` into a venv
   outside the tree; the toolchain image installs it at `/opt/spsdk`, and `scripts/image-tag.sh`
   hashes the pin files into the toolchain tag.
4. `scripts/ahab/sign-test.sh`, `scripts/ahab/container.yaml` and the `ahab-sign-test` target; the
   shell scripts under `scripts/ahab/` join `make build` and `make lint-shell`.
5. Docs: the Decision line in `signing-tool-options.md`, `signing-pipeline.md` (how to run).

## Marked MISSING in the config (no guessed values)

- The AHAB container version field a real device needs (anti-rollback `fuse_version`), and the
  container header version: IMX95RM and the i.MX 95 Security Reference Manual are not in
  `docs/references` (signing-tool-options.md U3).
- The SRK hash fuse values of a real device: same sources. The printed hash is the test PKI's only.

## musl and libuuu (resolved)

SPSDK 3.13.0 requires `libuuu`, which publishes only glibc (manylinux) wheels. On musl (the Alpine
devcontainer) pip installs its sdist, pinned by SHA-256 with its build backend
(`build-requirements.txt`): it compiles nothing and only packages NXP's prebuilt glibc `libuuu.so`,
which `nxpimage ahab export` and `verify` never load. The whole closure installs hash-checked on
musl, so the toolchain image carries the venv at `/opt/spsdk` (`SPSDK_VENV`); CI stages have no
network. `nxpuuu` (board flashing) would need that `.so` and is out of scope.

## Out of scope

HSM and go-xkms custody, CST cross-check (`CST_PATH` code unchanged), any real or production key,
any fuse write or life-cycle change, any board access, the platform image's real payloads.
