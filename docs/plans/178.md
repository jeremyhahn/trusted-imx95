## Pin-file consistency check, 2026-11-24

Dependabot-style bumps land on this row, and nothing offline checked `scripts/tool-pins.sh` or `scripts/ahab/requirements.txt` themselves. `scripts/pins-check.sh` now does, and `make build` (a CI stage) and `make pins-check` run it. It checks, naming the variable and the rule: each `PINNED_TOOLS` tool defines its version, repo, URL, SHA-256 and hold; the URL names the tool's repo and the release tag of its version; every SHA-256 is 64 lowercase hex; the Alpine and Python digests are `sha256:` plus 64 hex; the Debian snapshot is `YYYYMMDDTHHMMSSZ`; no tool has a URL without being in `PINNED_TOOLS`. For the requirements file, every requirement is `name==version` with at least one `--hash=sha256:<64 hex>`, and no name repeats.

It is offline and complements the network `make deps-check`: that says whether a pin is behind, this says whether the pin is well formed. `test/pins_check_test.sh` runs it on the real files and on scratch copies that each break one rule. Upgrading SPSDK stays a reviewed PR that re-resolves and re-hashes the closure, as the header of `scripts/ahab/requirements.txt` says.
