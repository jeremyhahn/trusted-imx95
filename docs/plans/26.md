# Plan: #26 hsm-self-defence, the A55 side (proposed, pending owner approval)

Objective: under owner ruling 1234 the Cortex-A55 Linux side calls the enclave's key (HSM)
API, so its HSM service must stop using keys, end its key-store sessions and not retry
when the Cortex-M7 runs its tamper response. This lane designs that reaction and the
message contract the M7's tamper event reaches the A55 with, so that `26-hsd-a55-2` can
implement a parser against it. The witness principle stands: no A55 observation alone
triggers key deletion. Everything is proposed, pending owner approval. Documentation only.

## Slices, in order

1. The design note `docs/hsm-self-defence/a55-tamper-response-design.md`: who does what,
   candidate channels (SCMI notification adapter, FuSa, Misc, direct M7-to-A55 path) and a
   provisional default, a 28-byte little-endian versioned record with event codes,
   validation order and byte-exact test vectors, the service state machine (normal,
   quarantined, terminal), what a compromised A55 can do, board validation list, questions.
   Test: block 3 of `test/hsm_docs_test.sh` (headings, "proposed, pending owner approval",
   "ruling 1234", a vector for every event code and every reject name, no `Closes`, links,
   finding ids, no private path), with three negative cases on scratch copies.
2. The `hsm-self-defence` row of `docs/SPEC.md` and the `hsm-self-defence` line of
   `ROADMAP.md` ("issue #26", "A55 side proposed, pending owner approval"): one changed
   line in each file. (The earlier note's link, question 6 and proposed SPEC wording went
   in with slice 1, because block 3 of the test checks the link.)

## Out of scope

- The M7's detection and response (trusted-firmware), the SM configuration
  (`system-manager-config`), key deletion, fuses, life-cycle steps, any board step.
- The parser and the service (`26-hsd-a55-2`).
- The `secure-key-handling` row's ruling-1234 wording (PR #169); other rows of SPEC and
  ROADMAP (PRs #169, #181, #182, #158).

## Open questions (carried in the note's Questions for the owner)

1. Channel: SCMI notification adapter as trigger plus a direct path for the full record?
2. Does the A55 acknowledge, and does the M7 resend its state to a late listener?
3. Is the test event accepted in production images?
4. Unknown event code: fail closed (quarantine) or ignore?
5. Must ending the key-store sessions leave the persistence writer running?
6. How does the M7's zeroisation request reach the enclave, if the M7 is not a caller of
   the HSM API (ruling 1234; tamper survey finding 5 leaves it unconfirmed)?
