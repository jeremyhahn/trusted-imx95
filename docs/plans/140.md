# Plan: #140 ftpm image build (configuration only)

Row branch `row/140-ftpm-image`. Provisional: the SPEC row `ftpm` is proposed, pending owner approval, and the
open questions in [docs/ftpm/README.md](../ftpm/README.md) stay open.

## Objective

Put the firmware TPM into the platform image as Yocto configuration: kernel driver, OP-TEE with the fTPM early TA,
tpm2-tools in the debug image. Nothing is built with bitbake in this row; the recipes are parsed and the TA source fetched (slice 4).

## Provisional defaults (the owner has not answered)

- NV storage on OP-TEE REE FS. RPMB off (`CFG_RPMB_FS=n`); no RPMB key is programmed, scripted or enabled.
  Limits: no rollback protection, NV lost on a rootfs reflash.
- TA: `optee_ftpm` 4.10.0 on `ms-tpm-20-ref`, pins as in docs/secure-world/build.md, an early TA.
- Kernel: `CONFIG_TCG_TPM=y`, `CONFIG_TCG_FTPM_TEE=y`, so `/dev/tpmrm0` exists once `tee-supplicant` runs.
- tpm2-tools in the debug image only.
- EK template not chosen in the image; the EK is created at first boot by provisioning.

## Slices

1. Kernel fragment `ftpm.cfg`, listed in the bbappend; both symbols in `kernel-required.txt`.
   Test: `test/platform_image_kernel_test.sh` checks them against `ftpm.cfg` and the bbappend naming it.
2. OP-TEE bbappend and an `optee-ftpm` recipe at the pinned revisions; REE FS, RPMB off, early TA.
   Test: a platform-image test that the pins match docs/secure-world/build.md and no RPMB key option exists.
3. tpm2-tools in the debug image; `docs/ftpm/build.md`; links from docs/ftpm/README.md and
   docs/platform-image/build.md. Every measured-boot gap stays listed.

4. Build-host parse (lane 140-ftpm-parse): `make platform-image-parse` passes with the fTPM recipes (meta-tpm joins
   the layers for tpm2-tools; the recipe drops `S`, takes the real license checksum). Docs record the result.

## Out of scope

A full bitbake image build, the board test, RPMB, fuses, life-cycle, the EK template,
U-Boot's TPM driver, measured boot (`CFG_TA_MEASURED_BOOT` stays off).
