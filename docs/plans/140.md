# Plan: #140 ftpm image build (configuration only)


Row branch `row/140-ftpm-image`. Provisional: the SPEC row `ftpm` is proposed, pending owner approval, and the
open questions in [docs/ftpm/README.md](../ftpm/README.md) stay open.

## Objective

Put the firmware TPM into the platform image as Yocto configuration: kernel driver, OP-TEE with the fTPM early TA,
tpm2-tools in the debug image. Nothing is built with bitbake in this row; the recipes are parsed and the TA source fetched (slice 4).

## Provisional defaults (the owner has not answered)

- NV storage on OP-TEE REE FS. RPMB off (`CFG_RPMB_FS=n`); no RPMB key is programmed, scripted or enabled.
  Limits: no rollback protection, NV lost on a rootfs reflash.
- TA: `optee_ftpm` 4.10.0 on `ms-tpm-20-ref`, pins as in docs/secure-world/build.md, an early TA.
- Kernel: `CONFIG_TCG_TPM=y`, `CONFIG_TCG_FTPM_TEE=y`, so `/dev/tpmrm0` exists once `tee-supplicant` runs.
- tpm2-tools in the debug image only.
- EK template not chosen in the image; the EK is created at first boot by provisioning.

9. Codex P1s from verify 5, all three fixed:
   - Ordering cycle: the BSP `tee-supplicant@.service` is `DefaultDependencies=no`, `Before=sysinit.target`; the wipe unit
     had the default dependencies (After=sysinit.target) and closed a cycle. It is now `DefaultDependencies=no`, with

   - Same-image reflash (security): the erasure is coupled to the flashing. `scripts/flash-rootfs.sh` is the only
     supported way to rewrite the root partition: it finds `root` and `tee-data` by GPT name, erases `tee-data`, then writes
     the rootfs, and refuses with nothing written if it cannot find both. It erases first, so an interrupted run never leaves
     a new rootfs beside the old NV. `test/flash_rootfs_test.sh` runs it on regular-file GPT images with a stub `mkfs.ext4`.
     The boot-time identity check stays as the second barrier. A raw root write outside the script is unsupported and keeps
     the NV.

    `optee-os` already depends on `optee-ftpm:do_deploy`. The task graph (`bitbake -g`) shows both edges.

11. Codex P1s from verify 6:
    - Security: `scripts/flash-rootfs.sh` took partition names from the GPT and split them in the shell, so a name such as
      `tee-data 0 1048576` could inject offsets. The Python reader now matches the exact names `root` and `tee-data` itself and
      prints four validated integers (in-disk, non-overlapping); a duplicate, missing, whitespace or control-character name is
      refused with nothing written. Tests cover a name with spaces and numbers, a newline, a tab, and a duplicate `tee-data`
      or `root`.
    - Reproducibility: the rootfs id embedded `DATETIME`. It is now the SHA-256 of the rootfs tree (paths, types, modes, link
      targets and file contents, less the id file), so identical inputs give identical bytes; the test asserts no clock variable.
